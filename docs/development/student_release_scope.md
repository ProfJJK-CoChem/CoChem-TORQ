# Student release scope and remaining full-SRS qualification gates

Reviewed 2026-10-07 against the current implementation SRS and source tree. This is a **scope/evidence audit**, not a scientific certification or deployment report. A test path below identifies the relevant executable check; its presence does not mean it passed. Consult actual run manifests/JUnit artifacts for pass, fail, skip, blocked and unrun status.

The current implementation provides a bounded real CPU teaching/validation route: explicit restricted electronic-structure calculations, optimized-coordinate checks, equilibrium moments/constants, harmonic characterization and explicitly labeled rigid-rotor screening. It preserves valid earlier stages when later requested spectroscopy is unavailable. These capabilities do not establish high-accuracy B0, centrifugal-distortion/hyperfine completeness or laboratory/astronomical identification accuracy.

GitHub Actions is the canonical calculation environment; GitHub Codespaces is the canonical interface. Local real-engine tests can validate software/numerical behavior. Actual remotely executed Actions runs and Codespaces user journeys, including immutable image/dependency identities and raw result artifacts, are separate deployment evidence. A workflow/Dockerfile/notebook alone cannot establish that evidence.

## Research and integration gates that prevent full-SRS completion

| Gate | Implemented starting point | Required remaining evidence |
|---|---|---|
| Exact revDSD-PBEP86-D4 | Conventional GKS-preserving OS/SS PT2, hybrid/D4 components and explicit numerical derivatives in `engines/revdsd.py`; ten genuine CPU machinery checks passed in the agent's local run | Original recipe/SI reconciliation including orbital generation, exact P86 variant and frozen core; matched independent native energy components; independently qualified derivative orders. Ordinary HF/MP2/D4 addition is not an exact revDSD implementation. |
| Rovibrational VPT2/B0 | Real energy-displacement force-field construction and vibrational perturbation/polyad machinery; B0 algebra accepts explicitly identified external corrections | Independent molecular force fields/solver comparisons, rotation-vibration alpha, Coriolis/resonance treatment and centrifugal-distortion outputs; authentic correction provenance and isotope/axis matching. Vibrational-only VPT2 does not establish B0. |
| Complete identification catalog | Internal finite-J rigid-rotor screening and strict export integrity | Qualified effective Hamiltonian, required distortion/hyperfine/tunneling terms, exact spin weights, dipole/intensity/population model, pinned SPCAT/fitter round trips and measured independent lines over a frozen band. |
| Large-amplitude/weak binding | Existing DVR safeguards and explicit missingness | Actual molecular PES and kinetic operator, boundary conditions, PI/spin symmetry, coupled torsion-rotation/VRT convergence and challenge benchmarks. Semirigid VPT2 is not general LAM spectroscopy. |
| Full method matrix | All 140 legacy row identities and explicit recipe registry | Exact supported engine/basis/reference/derivative/hardware tuples with raw calculation evidence for each enabled recipe. A documented row is not engine support or measured accuracy. Licensed engines require genuine site provisioning and independent validation. |
| BASE/TOPOS/SpycFit integration | Versioned identity/provenance handoffs and tests invoking real sibling serializers/consumers | Compatible remote BASE fenced task-service authority; actual SpycFit versioned consumer/schema; complete deployed cross-repository lifecycle and numerical convention round trips. |
| Scientific accuracy and uncertainty | Bounded [benchmark proposal](../../benchmarks/rotational-identification/preregistration.json) | Curated real references, accepted numerical/predictive targets and budgets, immutable registration, blind held-out execution and observable-specific error/coverage/failure reports. A proposal is not completed preregistration. |
| Canonical student deployment | Codespaces/interface, Actions workflow and per-engine image definitions | Real Actions image qualification/run artifacts; actual Codespaces submit/status/cancel/download/export evidence; operational quota/retention/recovery/security checks on every advertised platform. |

None of these gaps authorizes fabricated substitutes or an unsupported fallback. The complete spectroscopy route remains in scope; unavailable later-stage capabilities are blocked with a reason. The accepted scientific and architecture decisions are design authorization, not evidence that their research validation has completed.
