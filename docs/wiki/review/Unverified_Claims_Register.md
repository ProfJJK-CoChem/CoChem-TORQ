# Scientific and vendor claims requiring qualification

Reviewed 2026-10-07 against the supplied SRS/method matrix and the [preceding reference ledger](Scientific_References.md). Source baseline is repository commit `d7a4739a5f7d6f22ed659b32eeb4706bef16225e`; line numbers below locate the supplied documents in this checkout and may move during editing. Quoted phrases and section/cycle identifiers are the durable locators.

The earlier statement “some vendor and literature claims remain explicitly unverified” referred to the items recorded below. **Unverified does not mean false.** Some are unsupported in the supplied evidence; others have a specific internal contradiction or an inspected source demonstrating a narrower capability. The revised implementation SRS already rejects many of the unsafe generalizations. Preserving a historical document does not reinstate its claims as normative requirements.

Evidence states:

- **Not retrieved:** the primary text/manual was not available to this review; no truth judgment follows from access failure.
- **Incomplete support:** the cited evidence does not establish the exact TORQ claim, its scope, or a numerical guarantee.
- **Source conflict:** supplied statements conflict with one another or with inspected source. Resolve the exact version/method before selecting an implementation.
- **Incorrect as stated:** the assertion conflates distinct concepts or omits a necessary mathematical/scientific prerequisite.
- **Unexecuted:** source inspection supports an interface/capability, but the actual runtime integration or scientific result has not been demonstrated.

## What was verified, and what the remaining work means

The inspected evidence genuinely supports separate OS/SS double-hybrid terms, the DFTD4 revDSD dispersion table, the named schema exports, GPU4PySCF's documented limitations, single-writer HDF5 semantics, distinction between hashes/signatures, and Pyckett file roles. It does **not** certify TORQ's chemistry or deployment. The new protocol adds release-pinned Psi4 1.10 and DFTD4 3.7.0 source checks [P1–P3], plus PySCF 2.8.0 energy/derivative building blocks [P6]. **The user's D01 selection is to develop exact open-source revDSD**, with separate energy, orbital-response gradient and higher-derivative milestones. ORCA is an independent-reference candidate; CFOUR is an optional high-level spectroscopy/reference profile. Neither is silently made a production dependency of that selection.

The matrix's **319 numbered URLs** are mechanically indexed, not a fully verified publication bibliography. Claims outside the entries above still require a claim-to-source audit before publication. In particular, a citation's existence or a correct DOI does not establish that its source supports a new threshold, hardware guarantee, broad accuracy claim, or mechanism attributed to it. This register identifies the concrete outstanding issues from the previous conclusion; it does not pretend that every sentence in 319 sources has been reviewed.

Use these closure rules:

1. Attach complete bibliographic/version metadata and an exact page/table/code locator to each retained claim.
2. State the source's actual molecule/state/basis/method/hardware scope. Keep measured, derived, estimated and design-choice claims distinct.
3. Verify software capability using the selected version's authoritative documentation plus real integration evidence. Source exports alone are not numerical validation.
4. Remove, correct, or narrow claims contradicted by evidence. Keep genuinely inaccessible claims marked unresolved; do not replace them with plausible invented facts.
5. Claims of achieved accuracy, calibration, validated spectra or deployability require the corresponding executable evidence and independent scientific evaluation.

No quantum engine, proprietary manual, inaccessible publisher article, real experimental fit or astronomical identification was newly executed/validated in this document review. ORCA's manual remains denied through the normal proxy; CFOUR's prior denied request remains recorded. Continuing the code and typed-stage work does not require pretending those scientific validation gates have passed.
